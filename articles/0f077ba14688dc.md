ジェネリクスは〜や〜に便利ですよね。しかし、許容するジェネリクスの型を自由に設定できるようにするためにはちょっとしたテクニックを知ることが必要です。そうしたジェネリクスを便利に使えるようにするためのテクニックを紹介します。

## 遭遇した課題

API を利用したサーバー通信のレスポンスについて status の確認と body の返却の実装をさまざまな RemoteDataSource に記述していた。これを共通化したいと感じました。しかし2つの問題に遭遇しました。一部の POST や DELETE メソッドでは body を必要としません。 HTTP リクエストメソッドの種類に関わらず、1つの共通処理で status の確認と（必要な場合に限り） body の返却を行う `validatedBody()` を実装しようと考えました。

1. T が null を許容する場合のみ null を返せるようにできるのか？
2. T が void を許容できるのか？

## 課題を解決した小さなテクニック

```dart
T validatedBody<T>(Response<T> response) {
  if (!response.isSuccessful) {
    throw InvalidResponseStatusException(response: response);
  }

  // 1) body が null かつ T が null を許さない型なら例外
  if (response.body == null && (null is! T)) {
    throw InvalidResponseFormatException(
      'body should not be null',
      innerException: response.error,
    );
  }

  // 2) body が null かつ T が null を許容する型なら null を返す
  //    （T が int? / dynamic / void のときはこちらに入る）
  if (response.body == null && (null is T)) {
    return null as T;
  }

  // 3) それ以外は body が null ではないことが保証されるので返す
  return response.body!;
}
```
